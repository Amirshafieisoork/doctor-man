# دکتر من — DrMan

دکتر من یک وب‌سایت فارسی برای تفسیر آموزشی آزمایش، پرونده سلامت فردی و خانوادگی، پیگیری مراقبت، محتوای سلامت و ارتباط با پزشکان تأییدشده است. نتیجه هوش مصنوعی جایگزین تشخیص و درمان پزشک نیست.

## ساختار پروژه

- صفحات HTML فارسی و RTL، فونت محلی Vazirmatn و تم روشن/تیره.
- میزبانی Vercel؛ مسیرهای عمومی و خصوصی در `vercel.json` تعریف شده‌اند.
- یک تابع Serverless در `api/router.js` و handlerهای داخلی در `server/api`.
- Supabase PostgreSQL و Storage خصوصی؛ بررسی دسترسی و مالکیت اطلاعات در سرور.
- نشست امضاشده با cookie از نوع HttpOnly؛ اطلاعات مرورگر مبنای مجوز دسترسی یا اشتراک نیست.
- سرویس‌های هوش مصنوعی با رضایت کاربر و کنترل سهمیه در سرور.
- اتصال AI از حساب Free سرویس Groq؛ Qwen برای خواندن تصویر و GPT-OSS 120B برای تفسیر دادهٔ خوانده‌شده.
- پرداخت DigiPay با تأیید سرور؛ خرید زمانی فعال است که تنظیمات درگاه تکمیل شده باشد.

## اجرای محلی

نسخه Node در `.nvmrc` و وابستگی‌ها در `package-lock.json` قفل شده‌اند.

```sh
nvm use
npm ci --ignore-scripts --no-audit --no-fund
```

در صورت نیاز، `.env` را با نام متغیرهای `.env.example` آماده کنید. مقدارهای محرمانه نباید در Git ثبت شوند. صفحات استاتیک بدون کلید سرویس قابل مشاهده‌اند؛ قابلیت‌های آنلاین به تنظیمات واقعی نیاز دارند.

```sh
NODE_ENV=development npm run dev
```

سایت روی `http://127.0.0.1:3000` اجرا می‌شود. با `PORT` می‌توان پورت را تغییر داد. سرور محلی مسیرها، headerها و Router واقعی API را اجرا می‌کند و فقط فایل‌های عمومی را سرو می‌کند؛ محیط کامل Vercel و OIDC را شبیه‌سازی نمی‌کند. استفاده از HTTP برای درخواست‌های محلی فقط در محیط غیر production و Origin همسان روی loopback مجاز است.

## بررسی و آزمون

```sh
npm run check
npm test
npm run test:ui
```

- `check`: نحو JavaScript، فایل‌های JSON، لینک‌های محلی HTML/CSS و سازگاری مقصد API با artifact تابع Vercel را بررسی می‌کند.
- `test`: آزمون‌های سرور و رگرسیون مسیرها، aliasها، headerهای خصوصی، ۴۰۴، جلوگیری از افشای فایل‌های داخلی و اعتبارسنجی درخواست را اجرا می‌کند.
- `test:ui`: Chromium را روی اندازه‌های موبایل و دسکتاپ اجرا می‌کند؛ جهت RTL، ورود، پیش‌نمایش و محدودیت فایل، بازگشت خطا، سهمیه و وضعیت غیرفعال بودن پرداخت را بررسی می‌کند.

اگر `/usr/bin/chromium` موجود باشد، آزمون مرورگر از همان استفاده می‌کند. برای Chromium نصب‌شده در مسیر دیگر، `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` را تنظیم کنید. متغیر `PLAYWRIGHT_BASE_URL` امکان آزمون یک سرور محلی از پیش اجراشده را می‌دهد؛ در حالت پیش‌فرض Playwright یک سرور مستقل روی پورت ۳۱۰۰ ایجاد می‌کند.

آزمون‌های UI درخواست‌های API و سرویس‌های خارجی را در مرز مرورگر شبیه‌سازی می‌کنند و service worker را غیرفعال می‌کنند. این آزمون‌ها حساب واقعی، تحلیل AI، پرداخت یا تغییر پایگاه داده ایجاد نمی‌کنند. تأیید اتصال واقعی سرویس‌ها، مهاجرت‌های دیتابیس و پرداخت باید جداگانه روی محیط مجاز انجام شود. گزارش HTML، trace و تصویر خطا در `work/` ذخیره می‌شوند.

## تنظیم محیط و انتشار

فقط پروژه Vercel با نام `drman` باید به این مخزن متصل شود. مقصد تابع در تنظیمات legacy builds، `/api/router.js` است؛ حذف پسوند `.js` می‌تواند APIها و صفحات پویا را به ۴۰۴ بفرستد.

متغیرهای لازم در `.env.example` مستند شده‌اند. در production از HTTPS، `NODE_ENV=production`، کلید نشست قوی، کلیدهای معتبر سرویس و URL عمومی صحیح استفاده کنید. تا وقتی تأیید merchant و آزمون چرخه کامل DigiPay انجام نشده، درگاه باید در حالت آزمایشی یا غیرفعال بماند. پزشک فقط پس از احراز و تأیید حرفه‌ای در فهرست عمومی نمایش داده می‌شود.

پیش از انتشار، بررسی‌های محلی باید موفق باشند و وضعیت اتصال دیتابیس، هوش مصنوعی و پرداخت از طریق `/api/status` بررسی شود. آماده بودن متغیر محیطی به‌تنهایی صحت دسترسی سرویس یا چرخه پرداخت را ثابت نمی‌کند.

تنظیم AI رایگان از `/admin#ai-settings` انجام می‌شود. کلید حساب Free در فرم مدیر وارد و با کلید مستقل مشتق‌شده از `SESSION_SECRET` و AES-256-GCM ذخیره می‌شود؛ API هیچ کلید یا ciphertext را به مرورگر برنمی‌گرداند. دکمهٔ «آزمون اتصال رایگان» فقط برگهٔ ساختگی سرور را می‌خواند و اعداد، وضعیت‌ها و متن فارسی را کنترل می‌کند. حذف کلید، اتصال را غیرفعال می‌کند؛ تغییر `SESSION_SECRET` نیاز به ثبت دوبارهٔ کلید دارد.

مدل تصویری `qwen/qwen3.8-27b` در وضعیت preview و مدل متنی `openai/gpt-oss-120b` در وضعیت production سرویس Groq هستند. سقف فعلی حساب Free هر مدل ۳۰ درخواست در دقیقه، ۱۰۰۰ درخواست در روز، ۸۰۰۰ توکن در دقیقه و ۲۰۰۰۰۰ توکن در روز است؛ سقف واقعی در Console حساب نمایش داده می‌شود. هر تحلیل چند درخواست مصرف می‌کند و سهمیهٔ توکن می‌تواند زودتر تمام شود. درخواست‌های تصویری به دسته‌های حداکثر دو صفحه تقسیم می‌شوند و نتیجهٔ متنی باید تمام ردیف‌های خوانده‌شده را بدون تغییر عدد، واحد یا محدوده حفظ کند. پرشدن سهمیه، خطای روشن و قابل تلاش مجدد می‌دهد.

زمان اجرای تابع ۳۰۰ ثانیه، سقف کل تحلیل ۲۲۰ ثانیه و انتظار مرورگر برای تحلیل ۲۴۰ ثانیه است؛ ذخیرهٔ اصل فایل سقف مستقل ۶۵ ثانیه دارد. آزمون زندهٔ build فقط با `DRMAN_LAB_AI_PROBE` برابر SHA همان commit فعال می‌شود و به دو تصویر مصنوعی محدود است؛ در انتشار معمول هیچ درخواست مدل از build انجام نمی‌شود. اتصال واقعی تا ثبت کلید حساب Free تأییدشده قابل آزمون نیست.

مهاجرت `supabase/migrations/20261009034254_lab_analysis_quota_reservations.sql` رزرو اتمیک سهمیه تحلیل آزمایش را فراهم می‌کند. پیش از اجرای این نسخه، این مهاجرت باید روی همان پروژه Supabase اعمال شود. جدول رزرو و تابع‌های آن فقط برای `service_role` قابل استفاده‌اند و داده پزشکی در رزرو ذخیره نمی‌شود.

مهاجرت `supabase/migrations/20261012200142_close_public_lab_image_access.sql` سیاست عمومی قدیمی مخزن آزمایش را حذف می‌کند. این تغییر با تأیید مالک روی پروژه موجود اعمال شده است؛ دوباره اجرا نشود. خصوصی بودن bucket به‌تنهایی جای بررسی سیاست‌های Storage را نمی‌گیرد. دسترسی فایل‌های پزشکی از مسیر سرور و service proxy انجام می‌شود.

مهاجرت‌های ۱۴ اکتبر ۲۰۲۶ بازیابی رمز، نگهداری اصل فایل‌ها، بررسی مجوز پزشک، عملیات مدیریت، تیکت پایدار و چهار راهنمای سلامت را اضافه می‌کنند. این هفت مهاجرت روی پروژه اصلی اعمال شده‌اند و نام نسخه‌های محلی با تاریخچه سرور یکسان است. قبل از انتشار همین نسخه روی پایگاه داده دیگری، مهاجرت‌ها باید به ترتیب اجرا شوند؛ بررسی نشست به ستون `users.session_version` نیاز دارد.

تا زمان اتصال پنل پیامک، کاربر از `/auth#forgot` درخواست بازیابی ثبت می‌کند. مدیر پس از احراز هویت مستقل، از بخش درخواست‌های بازیابی پنل، لینک یک‌بارمصرف تولید و از راه ارتباطی مورد اعتماد در اختیار صاحب حساب می‌گذارد. لینک ۳۰ دقیقه معتبر است؛ تغییر رمز نشست‌های قبلی را باطل می‌کند. هیچ رمز یا توکن خامی در پایگاه داده ذخیره نمی‌شود و تغییر رمز به‌تنهایی کاربر را وارد حساب نمی‌کند.

پرونده سلامت عکس‌های JPEG/PNG/WebP و PDF تا ۴ مگابایت را نگه می‌دارد. اصل عکس آزمایش پیش از ارسال نسخه مناسب تحلیل، در پرونده ثبت می‌شود؛ خطای هوش مصنوعی عکس ثبت‌شده را حذف نمی‌کند. فایل‌های تاریخی که فقط نسخه پردازش‌شده دارند با همین عنوان نمایش داده می‌شوند. تصاویر قابل‌نمایش MRI و رادیولوژی پشتیبانی می‌شوند؛ نمایشگر DICOM خام در این نسخه وجود ندارد. لینک مشاهده فایل خصوصی و کوتاه‌مدت است.

تصویر مجوز پزشک خصوصی باقی می‌ماند. هوش مصنوعی فقط مشخصات و اشکالات احتمالی تصویر را بررسی می‌کند؛ تأیید حرفه‌ای پس از بررسی مرجع رسمی توسط مدیر انجام می‌شود. در پشتیبانی، تیکت و پیام کاربر هنگام قطع سرویس AI باقی می‌ماند؛ پاسخ مدیر یا توقف پاسخ خودکار، پاسخ‌های AI در حال پردازش را بی‌اثر می‌کند.

در پردازش حذف حساب، درخواست ابتدا وارد وضعیت processing و حساب بیمار مسدود می‌شود؛ سپس فهرست فایل‌ها، حذف Storage و نتیجه پاک‌سازی پایگاه داده بررسی می‌شوند. خطای پاک‌سازی، درخواست را برای تلاش دوباره مدیر در همان وضعیت نگه می‌دارد. آپلود و عملیات AI پس از مراحل طولانی، فعال بودن حساب را دوباره بررسی می‌کنند؛ این بررسی‌های برنامه، جای تراکنش اتمیک میان وضعیت حساب و همه نوشتن‌های هم‌زمان را نمی‌گیرند.

## دسترسی شبکه برای آزمون پیش‌نمایش

اگر محیط Codex به دامنه استقرار خطای CONNECT 403 می‌دهد، در تنظیمات Network محیط، دامنه‌های زیر را به Allowed hosts اضافه و تنظیمات را اعمال کنید:

```text
drman.vercel.app
drman-git-feat-production-ready-drman.vercel.app
```

برای آزمون URL اختصاصی یک استقرار، hostname همان URL نیز باید مجاز باشد. دامنه بدون `https://` و مسیر ثبت می‌شود. تنظیمات موجود Supabase و سرویس‌ها حفظ شوند. پس از بازشدن شبکه، برای پیش‌نمایش محافظت‌شده از احراز هویت مجاز Vercel استفاده کنید.

تست واقعی ثبت‌نام، ورود، تحلیل AI و پاک‌سازی حساب آزمایشی روی خود پیش‌نمایش باید قبل از merge و تغییر دامنه production تکمیل شود. آزمون‌های محلی مرورگر، APIهای خارجی را با داده مصنوعی پاسخ می‌دهند. فعال‌کردن پرداخت همچنان به اطلاعات merchant و آزمون واقعی DigiPay وابسته است.
